# Student Meal Planner — design handoff

Source of truth for how the web page should look and behave. The interactive mockups live in the Claude Design canvas "Student Meal Planner" (13 artboards); this folder holds everything a coding session needs to apply them to `public/index.html`.

Contents of `docs/design/`:

- `DESIGN.md` — this file: tokens, layout, components, states, and the list of changes to make.
- `braid.js` — drop-in vanilla JS that draws the "Threaded Pantry" reuse map as SVG (`ThreadedPantry.renderBraid`, `randomStrands`, `strandsFromPlan`).
- `threaded-pantry.html` — standalone p5.js explorer for the same algorithm (seed + sliders). Reference only, not shipped.
- `threaded-pantry-philosophy.md` — why the braid looks the way it does.
- `mockups/` — the artboard sources from the design canvas (`*.dc.html`, `canvas.json`). They are Design-canvas files, not runnable pages, but every screen's markup, copy and inline styles are readable there. Generated by `mockups/generate_mockups.py`.

Type (Google Fonts, `display=swap`):

- Headings: **Fraunces** 600, italic for the wordmark, day headings and hero. Sizes: wordmark 26px, section h2 34px (28px mobile), verdict figure 72px (56px mobile).
- Body: **Source Sans 3** 400/600, 16px / 1.45.
- Numbers, receipt, labels: **IBM Plex Mono** 400/500, 13.5px (12px mobile).

Radii: cards 16px, inputs/buttons 10–12px, pills 999px. Touch targets ≥ 44px. No shadows, no gradients, no illustrations — the only picture is the braid, drawn from data.

## 2. Layout

- Phone first: one column, 16px gutters, 390px reference.
- ≥ 960px: two columns, form 420px on the left (sticky is fine), results on the right, 40px gap, 48px page padding, max 1280px.
- Header: wordmark + "Mercadona · Spain" on the left; on the right a pill toggle `EN | ES` (active side filled green) and a round 44px theme button (moon / sun icon).

## 3. The form (left column)

In order:

1. `h2` "Your week".
2. **Quick start** presets as mono pills: `€30 · 1 · 5d`, `€40 · 2 · 5d`, `€60 · 2 · 7d`. Clicking fills budget/people/days.
3. **Grocery budget**: € prefix, 18px. Under it a live mono hint recomputed on every change: `≈ €2.00 per person per meal · 20 meals`. Below `€0.85` per person-meal the hint appends ` · below our €0.85 floor` — the user sees "not realistic" coming before submitting.
4. People / Days as two steppers side by side (− input +).
5. Meals to plan: three checkbox chips (Breakfast / Lunch / Dinner), real `<input type="checkbox">` inside a `<label>`; checked = green-soft fill + green border.
6. Diet: segmented control, 4 options (Everything / Pescatarian / Vegetarian / Vegan), active = green fill.
7. Allergies, Already at home, Don't want: chip inputs — chips with an × button, a text input, and a dashed round **+** button at the end.
8. Anything else: textarea, 3 rows.
9. Submit: full width, 56px, green, Fraunces 20px, "Plan my meals →".
10. Fine print: "Prices come from Mercadona packages. Every total is added up by code — the AI never touches a price."

While loading, the form stays visible at 55% opacity and is inert.

## 4. Right column by state

### Empty (before the first plan)
1. **Hero card**: the braid (`randomStrands(2209)`, 760×320 desktop, 358×230 mobile) on paper inside the card, then Fraunces italic h2 "One week, fourteen ingredients, nothing thrown away." and a muted paragraph explaining strand / knot / leftover.
2. **How it works**: five numbered steps, each with a mono badge on the right — `YOU` (grey), `AI` (amber), `CODE` (green). Steps 2 is AI, 3–5 are code (see copy in `mockups/Main.dc.html`). Ends with a green-soft callout "Whole packages, honest totals".

### Loading (up to 30 s)
Card with h2 "Planning 10 meals for 2 people…", the braid drawn only up to a vertical pen line at 56% width (clip-path), a mono caption `Day 3 of 5 — carrying the pantry forward` and `⏱ 12 s / 30 s`, an 8px progress bar, then a five-step checklist (done = green disc with check, active = spinner ring, todo = empty ring), and a mono status line like `Matching «garbanzos cocidos» → bote 400 g, €0.65`.

### Result — within budget
Order matters: verdict first, always above the fold.
1. **Verdict card** (green-soft bg, green-line border): small caps label with check icon, `€36.80` at 72px Fraunces + `of €40.00`, 10px progress bar filled to 92%, mono row `92% of €40.00` / `€3.20 left`.
2. **Three stats** in a row (stack on mobile): `€1.84` per person per meal · `€4.10` of food left over · `9 / 14` ingredients used twice or more, each with a one-line muted note.
3. **Reuse map** card: `renderBraid(el, strandsFromPlan(plan), { labels: true, dayCosts })` — labelled rows, knots on cooked days, amber beads for leftovers, dashed = at home, per-day cost bars under the day columns. Legend below: hollow knot "cooked that day", amber dot "left over, sized by how much", dashed line "from your pantry".
4. **What's left on Friday** card: two columns — "Keeps in the cupboard" (green-soft) and "Use within the week" (amber-soft), name + mono quantity per row; button "↻ Plan next week from these leftovers" which pre-fills *Already at home*.
5. **Your 5 days**: one article per day, `Day 1 · Mon` in Fraunces italic with the day's cost in mono on the right. Each meal is a 56px `<button aria-expanded>` row: small-caps LUNCH/DINNER label (64px column), dish name in Fraunces 20px + `35 min` mono, then pills: grey mono for ingredients, green `↻ reused from rice · Day 1`, amber `leftover → Day 3`. Expanded body: two columns (220px Ingredients list / Method ordered list).
6. **Shopping list** card: header with "Copy" and "Print" buttons (icon + text). The receipt itself: paper background, 1px border, 4px radius, IBM Plex Mono. Centered `MERCADONA` / `SHOPPING LIST · 22/09/2026`, then a 5-column grid header between two dashed rules: Item / Need / Buy / Left / €. Aisle headings in small caps. Rows: item (ellipsis), need (muted), buy (bold), left (amber when non-zero, muted "—" otherwise), cost right-aligned. Items already at home: struck through, `at home` in green, `0.00`. Footer: Subtotal (bold) / Budget (muted) / Remaining (green) or Over (red), then `RECIPES BY AI · TOTALS BY CODE`.

### Result — over budget
Same page with: verdict card in red tokens, bar full red with a black tick at the budget position, mono `€30.00 = 82%` / `over by €6.80`; a muted line "You're €6.80 over. One change below is enough."; then a **What you can change** card (red-line border) listing 3 concrete changes, each: title, note, mono saving in green (`−€5.90`) and an "Apply" button that re-plans. The rest (stats, reuse map, plan, receipt) follows.

### Result — not realistic
No plan, no receipt. Verdict card (card bg, red-line border): red small-caps label with alert icon, Fraunces 44px "We can't plan this honestly", the maths in one sentence, and a red-soft strip with `€0.29` per person per meal · 42 meals. Then a "Why" card with 3 numbered reasons, then "Try one of these": four option buttons in a 2×2 grid (1 column on mobile), each Fraunces title + muted note, and the closing line "No plan was generated. We'd rather say so than hand you a list you can't afford."

### Mobile results
A 48px summary bar at the top (`‹ €40 · 2 · 5d · lunch + dinner` … `✎ Edit`) that scrolls back to the form; all sections stack; stats become one column; the reuse map uses `scale: 0.8`; day-plan label column shrinks to 52px.

### Print (receipt)
A4, white, black ink, mono 12.5px: app name in Fraunces italic, subtitle line, right-aligned "Plan for: 2 · 5 days · Lunch + Dinner / Tick as you shop", then the same receipt grid with a 12px checkbox column, totals, and the footer line. `@media print` should hide everything except this block.

## 5. Bilingual
Every string exists in EN and ES (all copy is in `mockups/generate_mockups.py`, dicts `EN` and `ES`). Money formats as `€36.80` in EN and `36,80 €` in ES. Dish names change language too.
